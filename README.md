# ProTradingRoom reference application

The captured AngularJS desktop and marketplace clients run against a local Node.js backend with Docker-managed Janus, FFmpeg, MediaMTX, and Mailpit. This checkout provides the working reference and captured contracts for the later stack migration.

## Start

Use Node.js 24 or later and Docker Compose with Docker Desktop running.

```sh
npm ci
npm run setup
npm run docker:up
npm run accounts:provision
```

Open [the account portal](http://localhost:3031/ptrApp) or [the marketplace](http://localhost:3031/mp/). Mail arrives in [the local Mailpit inbox](http://localhost:8026).

Account provisioning creates business-owner, enterprise-owner, delegated-admin, room-admin, presenter, and participant credentials. It also creates scoped API credentials and room JWT signing secrets. The private credential file lives in the Docker data volume. Follow [the account instructions](docs/accounts.md) to copy it into the ignored `secrets/` directory.

The setup command generates private installation secrets in `.env`. Supported deployment settings are listed in `.env.example`. The supplied services bind to localhost and preserve application data in named Docker volumes. `npm run docker:down` stops the stack while retaining its volumes.

## Verify

```sh
npm run repo:check
npm run format:check
npm test
PTR_TEST_PHP_DOCKER=1 node --test test/wordpress.test.js
PTR_MAILPIT_INTEGRATION=1 node --test test/mailpit.integration.test.js
npm run test:browser:docker
npm audit
```

The isolated browser runner uses the official Playwright image with synthetic devices. It verifies role logins, tenant isolation, marketplace entry, free membership access, direct WebRTC recording, and OBS playback. It temporarily enables the local QA pages and disables them when finished. Its artifacts are stored in ignored `test-results/`. Provider integration tests use local sinks or mocked provider responses.

GitHub Actions runs the source checks, tests, image build, and isolated browser suite. `npm run format` formats maintained application source while preserving the captured bundles and assets.

## Runtime and providers

- `src/` contains HTTP APIs, authorization, account management, courses, billing, room control, and provider adapters.
- `public/` contains the captured desktop, detached-chat, marketplace clients, and local vendor assets.
- `docker/` configures private Janus, recording conversion, and authenticated OBS ingestion.
- `scripts/` contains setup, account provisioning, evidence generation, and repository checks.
- `test/` contains API, security, provider, media, and browser regressions.
- `integrations/wordpress/` implements the captured JWT shortcode contract.
- `contracts/` preserves captured evidence, provenance, and implementation/verification status.

SMTP uses Mailpit locally. Optional Stripe, Twilio Voice/SMS, X, FCM, S3, Vimeo, Giphy, CAPTCHA, and TURN settings are configured through `.env.example` and the captured room settings. Actual provider credentials come from their issuing accounts. Installation secrets and local application credentials are generated by the setup and provisioning commands.

OBS uses `rtmp://localhost:1936` locally and a random per-session publishing path. A two-second keyframe interval supports prompt playback. Its control API remains inside Docker. Remote WebRTC access requires deployment-specific TLS, ICE/TURN, public media addresses, and firewall configuration.
